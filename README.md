# ServiceUP

CRM для сервисного центра по ремонту техники: учёт заказов, клиентов, сотрудников,
финансов, печать актов приёма/выполненных работ и мобильная PWA-версия для доступа
с телефона.

## Возможности

- **Заказы (устройства в ремонте)** — приём, диагностика, работы, статусы, приоритеты,
  фото, история изменений; оптимистичная блокировка на запись (`version_id`) и
  необязательная пессимистичная блокировка на редактирование (см.
  `managers/locking.py`).
- **Клиенты и история ремонтов** — карточка клиента со всеми его заказами,
  экспорт в CSV/JSON.
- **Сотрудники** — учёт без обязательной авторизации; выбранный "текущий сотрудник"
  проставляется в `created_by`/`updated_by` заказов.
- **Финансы** — доход/расход по заказам, статистика на дашборде.
- **Акты приёма/выполненных работ** — визуальный редактор шаблона (логотип, цвет,
  шрифт, набор и порядок полей, условия/гарантия, drag-and-drop) с живым PDF-превью
  (`reports/report_editor.py`), плюс импорт уже существующего акта из PDF/XLSX/DOCX —
  редактор читает текстовый слой файла и подбирает набор/порядок полей под него
  (`reports/act_importer.py`).
- **Плагины** — `plugins/clients`, `plugins/employees`, `plugins/orders` — модули со
  своей таблицей БД, подключаемые через ядро (`core/kernel.py`) и заменяемые
  реализацией репозитория (интерфейс `I*Repository` + `SqlAlchemy*Repository`,
  регистрация через `core.plugin_system.PluginManager.discover()`).
- **PWA** — Flask-сервер (`pwa/server.py`) отдаёт мобильный веб-интерфейс в локальной
  сети: тот же Database facade, что и десктоп, изменения видны в реальном времени.
- **Самообновление** — `utils/update_manager.py` проверяет GitHub Releases
  (`releases.atom`, без лимита API, с фолбэком на `api.github.com`), сверяет версии по
  PEP 440, скачивает и проверяет SHA256 нужного платформенного бинарника, делает
  бэкап перед установкой и перезапускается.

### Два интерфейса

При запуске бинарника показывается выбор интерфейса (можно запомнить в настройках):

- **Классический** (`gui/`, customtkinter) — полнофункциональный, актуальный вариант.
- **Flet** (`gui_flet/`, открывается в браузере) — второй, более лёгкий фронт поверх
  того же ядра и той же БД. Пока покрывает дашборд, заказы (список/поиск/фильтр по
  статусу/создание/редактирование/печать акта/смена статуса) и настройки
  (тема, проверка обновлений). **Не перенесены**: сам редактор шаблонов акта,
  справочники (тип устройства/бренд — во Flet просто текстовые поля), сотрудники,
  фото к заказам, вкладка "Финансы", бэкап/лицензия/админ-настройки БД — для них
  нужен классический интерфейс.

## Запуск из исходников

```bash
python -m venv .venv
.venv/Scripts/activate   # Windows
pip install -r requirements.txt
python main.py
```

Полезные флаги (`python main.py --help`):

| Флаг | Действие |
|---|---|
| `--ui=classic` / `--ui=flet` | запустить конкретный интерфейс без диалога выбора |
| `--no-update` | не проверять обновления при старте (актуально для frozen-сборки) |
| `--version` | показать версию и выйти |

## Сборка бинарников

```bash
python build.py --clean
```

Собирает через PyInstaller под текущую ОС (`ServiceUP-windows.exe` /
`ServiceUP-linux` / `ServiceUP-macos`). CI (`.github/workflows/build.yml`) делает то же
самое на всех трёх ОС при пуше тега `v*`, прикладывает SHA256-суммы и публикует релиз
на GitHub (как pre-release для тегов с `a`/`b`/`rc`).

## Версионирование

[PEP 440](https://peps.python.org/pep-0440/): `1.0.0b4` и т.п. Единственный источник
правды — `version.txt`; `pyproject.toml` синхронизируется с ним вручную при релизе.

## Архитектура

- `core/kernel.py` — DI-ядро (`ServiceUpCore`), реестр модулей, шина событий.
- `database/` — SQLAlchemy ORM (`sqlalchemy_database.py` + `facade/*_mixin.py`) поверх
  инфраструктурного слоя (`db_core.py`: соединение, сессии, кэш запросов). Легаси
  raw-sqlite3 класс (`db_manager.py`) сохранён только для миграции старых клиентских БД.
- `plugins/` — модули, владеющие своей таблицей, за интерфейсом репозитория.
- `gui/` / `gui_flet/` — два независимых фронта поверх одного и того же ядра.
- `reports/` — генерация PDF-актов (`report_renderer.py`) и их визуальный редактор
  шаблонов (`report_editor.py`, `act_importer.py`).
- `pwa/` — мобильный REST API + статика PWA.
- `TODO_RBAC_ROADMAP.md` — единственный сохранённый в корне заметочный файл: план
  ролевой модели/авторизации сотрудников (пока не реализована).
