## Исправленные ошибки в процессе тестирования

### 1. Ошибка `fmt_money()` при дробных значениях
**Проблема:**
```python
ValueError: invalid literal for int() with base 10: '7500.0'
```

**Причина:** Функция `fmt_money()` не обрабатывала строковые представления float.

**Решение:** Добавлена обработка исключений в `/workspace/database/facade/shared.py`:
```python
def fmt_money(value: float | None) -> str:
    if value is None:
        return ""
    try:
        float_value = float(value)
        if float_value.is_integer():
            return str(int(float_value))
        return f"{float_value:.2f}"
    except (ValueError, TypeError):
        return str(value)
```

### 2. Некорректное использование API БД
**Проблема:** Тесты использовали несуществующие параметры методов.

**Решение:** Исправлены вызовы методов на соответствующие реальному API:
- `get_devices_by_filters(search_query=...)` → `search_devices(search_text=...)`
- `get_devices_by_filters(status=...)` → `get_devices_by_filters(status_filter=..., priority_filter=...)`

### 3. Ошибка шины событий
**Проблема:** Передача строки вместо объекта Event.

**Решение:** Создан правильный объект события:
```python
from core.events.event_bus import Event
test_event = Event(event_type="TestEvent", data={"message": "test"})
```

## Архитектурные принципы соблюдены

✅ **Single Entry Point** - все взаимодействия через ядро  
✅ **Facade Pattern** - БД доступна через Database facade  
✅ **Dependency Inversion** - зависимость от абстракций (DI контейнер)  
✅ **No Direct DB Access** - никаких прямых SQL запросов в тестах  
✅ **Module Isolation** - модули взаимодействуют только через ядро
